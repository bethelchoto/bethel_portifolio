🚲 BikeDelivery Platform

Services Overview

1. Discovery Server (Port 8761)

Netflix Eureka service registry. All microservices register here for dynamic service discovery. The gateway and Feign clients use Eureka to resolve service URLs via lb://service-name.

2. API Gateway (Port 8080)

Central entry point for all client requests. Features:

  • JWT Authentication Filter — validates tokens on protected routes
  • Rate Limiting — Redis-backed request throttling
  • Circuit Breakers — Resilience4j per-service circuit breakers (sliding window: 10, failure threshold: 50%, half-open calls: 3)
  • Timeout — 5-second timeout per request
  • CORS — configured for cross-origin access
  • Fallback — /fallback endpoint returns graceful error when services are down
  • Load Balancing — client-side via Eureka
3. Auth Service (Port 8081)

Handles user registration and authentication using stateless JWT. Tokens expire after 24 hours. The JWT secret is shared across services that need to validate tokens.

4. User Service (Port 8082)

Manages customer profiles with full CRUD operations and paginated listing. Connected to user_db.

5. Rider Service (Port 8083)

Manages rider profiles, real-time location tracking, and availability status. Features:

  • Redis GeoSpatial — stores rider locations using GEOADD/GEORADIUS for O(log n) proximity queries
  • WebSocket — broadcasts rider locations to connected map clients every 3 seconds
  • Live Map — Leaflet.js dark-themed interactive map at /map
  • Delivery Tracking — real-time delivery tracking page at /map/tracking
  • Status Management — online/offline/busy/available state machine
6. Delivery Service (Port 8084)

Core business logic for the delivery lifecycle. Manages the full flow from request to completion. Publishes Kafka events at each stage. Uses Feign to call Pricing Service for price calculation.

7. Matching Service (Port 8085)

Listens for delivery-created Kafka events and automatically matches deliveries with nearby available riders. Uses an expanding radius algorithm (5km → 10km → 15km) to find the best rider. Calls Rider Service via Feign to mark the matched rider as busy.

8. Pricing Service (Port 8086)

Calculates delivery prices using a configurable formula with surge pricing support:

  • Base fare + per-km rate + per-minute rate + service fee
  • Surge multiplier cached in Redis
  • Minimum fare enforcement
9. Payment Service (Port 8087)

Processes payments with idempotency (via Idempotency-Key header) to prevent duplicate charges. Supports refunds. Publishes payment-completed events to Kafka.

10. Notification Service (Port 8088)

Consumes Kafka events and dispatches notifications via email, SMS, and push (stub implementations ready for real provider integration).

Pricing Algorithm

The pricing service calculates delivery cost using:

price = baseFare + (distanceKm × perKmRate) + (estimatedMinutes × perMinuteRate) + serviceFee
finalPrice = max(price × surgeMultiplier, minimumFare)

Default Configuration

Parameter Value
Base Fare$2.00
Per km Rate$1.20
Per Minute Rate$0.15
Service Fee$0.50
Minimum Fare$3.00
Surge MultiplierDynamic (cached in Redis)

Example: A 5km delivery estimated at 15 minutes with no surge:

$2.00 + (5 × $1.20) + (15 × $0.15) + $0.50 = $2.00 + $6.00 + $2.25 + $0.50 = $10.75

Rider Geo-Matching

The Matching Service uses Redis GeoSpatial commands for O(log n) rider proximity search:

  1. Location Storage — riders update their GPS coordinates, stored via GEOADD riders:locations longitude latitude riderId
  2. Proximity Query — when a delivery is created, GEORADIUS finds all available riders within range
  3. Expanding Radius — if no rider is found within 5km, the search expands to 10km, then 15km
  4. Best Match — closest available rider is selected and marked as busy
  5. Real-time Updates — the Rider Service tracks online/offline/busy/available status in a Redis Set

Live Map Tracking

The Rider Service includes a real-time map visualization powered by Leaflet.js and WebSocket.

How It Works

  1. Browser connects to WebSocket at ws://localhost:8083/ws/rider-location
  2. Server broadcasts all active rider positions every 3 seconds
  3. Map renders rider markers on a dark-themed OpenStreetMap layer
  4. Markers update in real-time as riders move

Getting Started

Prerequisites

  • Java 24 (JDK)
  • Maven 3.9+
  • Docker & Docker Compose
  • Git

Build the Project

# Clone the repository
git clone <repository-url>
cd ride_system

# Build all 11 modules
mvn clean package -DskipTests

Running with Docker Compose

# Start everything (infrastructure + all services)
docker-compose up -d

# Watch logs
docker-compose logs -f

# Stop everything
docker-compose down

Running Individual Services

# 1. Start only infrastructure
docker-compose up -d bike-postgres bike-redis bike-zookeeper bike-kafka

# 2. Wait for infrastructure to be healthy
docker-compose ps

# 3. Start Discovery Server first (required by all services)
cd discovery-server
mvn spring-boot:run

# 4. Start any service you need
cd ../auth-service
mvn spring-boot:run

Running with Kubernetes

# Deploy infrastructure & services
kubectl apply -f k8s/namespace.yml
kubectl apply -f k8s/infrastructure/
kubectl apply -f k8s/services/
kubectl apply -f k8s/ingress.yml

Quick Test Guide

After starting the platform, test the full delivery flow:

# 1. Register a user
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","password":"password123","fullName":"John Doe","phone":"+1234567890"}'

# 2. Login to get JWT token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","password":"password123"}' | jq -r '.data.token')

# 3. Create a customer profile
curl -X POST http://localhost:8080/api/customers \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"email":"john@example.com","firstName":"John","lastName":"Doe","phone":"+1234567890"}'

# 4. Register a rider
curl -X POST http://localhost:8080/api/riders \
  -H "Content-Type: application/json" \
  -d '{"email":"rider@example.com","firstName":"Jane","lastName":"Smith","phone":"+0987654321","vehicleType":"BICYCLE"}'

# 5. Set rider online and update location
curl -X POST http://localhost:8080/api/riders/1/online
curl -X POST http://localhost:8080/api/riders/location \
  -H "Content-Type: application/json" \
  -d '{"riderId":1,"latitude":-26.2041,"longitude":28.0473}'
