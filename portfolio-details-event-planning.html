🎈 EventPlanner API Backend

A production-ready, highly modular monolith backend for the EventPlanner ecosystem — SaaS Marketplace for event planning, booking, and real-time vendor collaboration.

Built with TypeScript 6, Node.js, Express 5, Prisma ORM (custom MariaDB adapter), Socket.io (WebSockets), Vercel Blob for media assets, and Nodemailer for secure transactional email dispatching. Deployed serverless on Vercel with full self-hosted raw HTTP fallback support for real-time WebSocket state synchronisation.

Domain Model & Features Overview

The platform uses a feature-based modular directory design (/src/features) to ensure high cohesion and maintainable separation of concerns:

👤 1. Authentication & User Accounts
  • Stateless Session Security: Employs cryptographically signed JSON Web Tokens (JWT) for access controls.
  • Two-Step Email Activation: Standard registration dispatches a secure 6-digit verification OTP through SMTP to mark accounts as active.
  • Role-Based Access Control (RBAC): Restricts secure routes based on user type (USER, VENDOR, ADMIN).
🎪 2. Event Planning
  • Unified Planner Dashboard: Planners can build custom events, set strict date limits, define overall budgets, and display custom cover flyers.
  • Aggregated Analytics: Auto-gathers and updates the event's booking commitments, budget limits, actual expenditures, and remaining capital.
💼 3. Vendor Profiles Marketplace
  • Category Taxonomy: Profiles are strictly cataloged by service specialties (CATERING, VENUE, PHOTOGRAPHY, etc.).
  • Rich JSON Attributes: Houses flexible structure models for pricing tiers and calendar availability models.
  • Discovery Filters: Advanced query parameters mapping keywords, location boundaries, service pricing tiers, and rating scales.
📅 4. Booking Scheduler
  • Strict Date Locks: Utilizes database-enforced unique constraints ([vendorProfileId, eventDate]) to completely eliminate dual-booking vulnerabilities.
  • Lifecycle Engine: Progresses reservations through strict, audited stages from request inception to paid confirmation.
💰 5. Event Budget & Expenses
  • Sub-Event Cost Logger: Planners log dynamic bills, categorize charges, and connect expenses directly to approved vendor bookings.
  • Visual Progress Metrics: Evaluates allocated event budget against real aggregated costs to guard against overspending.
📝 6. Task Management
  • Interactive Event Checklist: Tracks specific, deadline-bound todo tasks linked to parent events.
  • Activity Metrics: Generates real-time statistics covering completed tasks, progress ratios, and pending deadlines.
💬 7. Real-Time Chat System
  • State-Synchronized Messaging: Implements secure Socket.io channels to broker live communication between event planners and vendors.
  • Chat Enhancements: Supports live typing signals, unread counter badges, and immediate message persistence.
🔔 8. Instant Notifications
  • Status Sync Engine: Broadcasts instant real-time websocket and database-persisted notifications for actions (e.g., vendor bookings, inbox messages).
💳 9. Transaction Processing & Subscriptions
  • Commission Splitter: Stub models tracking custom commission fees per booking.
  • Stripe Transaction Register: Processes secure booking transactions and handles premium subscriptions for vendors.
⭐ 10. Reviews & Ratings
  • Aesthetic Scoreboards: Users write star ratings and written testimonials for approved vendors.
  • Dynamic Average Rating: Recalculates and aggregates overall vendor ratings automatically.

Getting Started

Prerequisites

  • Node.js v22.x or v24.x (LTS)
  • NPM v10.x+
  • Prisma CLI (auto-configured in package dependencies)
  • Access to a MariaDB or MySQL server instance

Environment Configuration

Create a .env file in the root directory:

PORT=5000
NODE_ENV=development

# Database connection parameters (MariaDB cloud instance)
DB_HOST=your-mariadb-host.com
DB_PORT=10850
DB_USER=avnadmin
DB_PASSWORD=your-secure-password
DB_NAME=defaultdb

# Unified Prisma connection string (SSL required for Aiven MariaDB instances)
DATABASE_URL="mysql://avnadmin:your-secure-password@your-mariadb-host.com:10850/defaultdb?connect_timeout=30&pool_timeout=30&allowPublicKeyRetrieval=true&sslmode=required"

# SMTP Configuration (Requires Gmail App Password)
GMAIL_USER=example@gmail.com
GMAIL_APP_PASSWORD=xxxx-xxxx-xxxx-xxxx

# Direct Asset Storage Upload token (Vercel Blob)
BLOB_READ_WRITE_TOKEN="vercel_blob_rw_xxxxx"

# JSON Web Token Secret
JWT_SECRET="generate-a-long-random-alphanumeric-string-for-access-tokens"
💡 Generating Gmail App Passwords:

Do NOT use your standard email password. Enable Two-Step Verification inside Google Settings, search App Passwords, generate a new app pass named EventPlannerBackend, and copy the resulting 16-character string into GMAIL_APP_PASSWORD.

Database Initialization

  1. Install Dependencies: 
    npm install
  2. Generate Prisma Client: 
    npx prisma generate
  3. Deploy Database Schema Structure: 
    npx prisma db push
  4. Seed System Base Profiles: 
    npx prisma db seed

Running the Server

Development Environment (With Watcher):

npm run dev

Production Build (Compiles to JS):

# Transpile source to JS
npm run build

# Execute production bundle
npm run start

Deployment & Vercel Optimization

This repository is optimized to deploy serverless on Vercel via vercel.json:

{
  "version": 2,
  "builds": [
    {
      "src": "src/index.ts",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/(.*)",
      "dest": "src/index.ts"
    }
  ]
}
⚠️ Critical Gotcha regarding local TSC execution:

If you run the raw typescript compiler tsc locally, it compiles .js, .js.map, and .d.ts files directly next to your .ts files inside /src.

Due to ESM relative import rules (import './controller.js'), Node.js prioritizes existing compiled .js files in /src over the updated .ts source. As a result, Vercel will continue serving outdated API behavior even after you make updates to your TS files.

The Prevention Fix:

If you experience outdated responses on Vercel:

  1. Purge all local build outputs within /src:
    • PowerShell:
      Get-ChildItem -Path src -Recurse -Include "*.js","*.js.map","*.d.ts","*.d.ts.map" | Remove-Item -Force
    • Unix Shell:
      find src -type f \( -name "*.js" -o -name "*.js.map" -o -name "*.d.ts" -o -name "*.d.ts.map" \) -delete
  2. Ensure you have "outDir": "./dist" configured in tsconfig.json.
  3. Commit clean /src folders and push to trigger a fresh Vercel compilation.
Serverless vs WebSocket Support
  • Websocket Limitation on Vercel: Vercel serverless execution modules do NOT support persistent TCP/WebSocket connections. When deployed on Vercel, the real-time chat features fallback gracefully.
  • Dual Execution Mode: This backend is coded to detect serverless targets (process.env.VERCEL === '1'). If serverless mode is detected, Express functions normally via HTTP routes. For persistent server environments, raw HTTP is created dynamically to power fully active WSS connections at port 5000.

Quick Test Guide

Step 1: Log in with the Seeded User

Log in as the standard user profile seeded during DB setup:
Email: userchots@eventplanner.com
Password: 1234567890

curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"userchots@eventplanner.com","password":"1234567890"}'
Step 2: Register a Vendor Profile

Log in as the seeded vendor profile:
Email: mwanawevhu@eventplanner.com
Password: 1234567890

# 1. Log in as vendor
VENDOR_TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"mwanawevhu@eventplanner.com","password":"1234567890"}' | jq -r '.token')

# 2. Create the vendor profile
curl -X POST http://localhost:5000/api/vendors/profile \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $VENDOR_TOKEN" \
  -d '{
    "businessName": "MwanaWevhu Events",
    "description": "Premium floral arrangement & coordination services",
    "category": "PLANNER",
    "pricing": {"baseFee": 500, "hourlyRate": 75},
    "availability": {"days": ["MON", "WED", "FRI"], "slots": ["MORNING", "AFTERNOON"]},
    "address": "12 Main St, Harare",
    "phone": "+26377123456"
  }'
Step 3: Approve the Vendor (Admin Action)

Administrative accounts verify and approve listings:
Email: admin@eventplanner.com
Password: 1234567890

# 1. Log in as Admin
ADMIN_TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@eventplanner.com","password":"1234567890"}' | jq -r '.token')

# 2. Fetch the pending vendor list
PENDING_VENDORS=$(curl -s http://localhost:5000/api/admin/vendors?approved=false \
  -H "Authorization: Bearer $ADMIN_TOKEN")
echo $PENDING_VENDORS

# 3. Approve vendor by their user ID
VENDOR_ID=$(echo $PENDING_VENDORS | jq -r '.[0].id')
curl -X PATCH http://localhost:5000/api/admin/vendors/$VENDOR_ID/approve \
  -H "Authorization: Bearer $ADMIN_TOKEN"
Step 4: Create an Event & Book the Vendor
# 1. Create a dynamic Event container
EVENT_RES=$(curl -s -X POST http://localhost:5000/api/budget/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $USER_TOKEN" \
  -d '{"name": "Spectacular Autumn Gala", "date": "2026-10-15", "budget": 15000.00}')
EVENT_ID=$(echo $EVENT_RES | jq -r '.id')

# 2. Fetch public vendors
VENDORS=$(curl -s http://localhost:5000/api/vendors?category=PLANNER)
VENDOR_PROFILE_ID=$(echo $VENDORS | jq -r '.[0].id')

# 3. Book the approved vendor
curl -X POST http://localhost:5000/api/bookings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $USER_TOKEN" \
  -d "{
    \"vendorProfileId\": \"$VENDOR_PROFILE_ID\",
    \"eventDate\": \"2026-10-15T00:00:00.000Z\",
    \"totalAmount\": 1200.00,
    \"notes\": \"Secure the floral theme setup for main auditorium.\",
    \"eventId\": \"$EVENT_ID\"
  }"
Step 5: Test WebSockets Real-Time Messaging
import { io } from "socket.io-client";

const socket = io("http://localhost:5000", {
  auth: { token: "PASTE_YOUR_USER_BEARER_JWT_HERE" }
});

// Join target conversation
socket.emit("joinConversation", { conversationId: "PASTE_CONVERSATION_UUID" });

socket.on("joinedConversation", ({ conversationId }) => {
  console.log(`Joined active chat room: ${conversationId}`);
  socket.emit("typing", { conversationId });
});

// Listener for typing status
socket.on("userTyping", ({ conversationId, userId }) => {
  console.log(`User ${userId} is currently typing...`);
});

// Transmit chat message payload
socket.emit("sendMessage", {
  conversationId: "PASTE_CONVERSATION_UUID",
  content: "Hi, I have successfully locked in our autumn booking. Can we review the color layouts?"
});

// Listener for incoming message broadcasts
socket.on("newMessage", (msg) => {
  console.log("New Message Received:", msg);
});
